# Contributing

Thanks for helping improve this package.

## Ground rules

- This package implements a contract shared with the Node.js package `@bijayx/iap-guard`
  (`SPEC.md`). Changes to statuses, error codes, normalization or ownership rules must be made
  in the shared specification first and applied to both packages.
- The test fixtures in `tests/fixtures` are generated by the specification's fixture generator
  and shared with the Node.js package. Do not edit them by hand.
- Never log or include private keys, access tokens, JWTs, the account-token secret or user ids in
  exceptions, logs or test output.
- Tests must not call Apple or Google. Use `Http::fake()` and the fixtures.
- No runtime dependencies beyond `illuminate/*` and `ext-openssl`.

## Setup

```bash
git clone <your fork>
cd iap-guard-laravel
composer install
```

## Before opening a pull request

```bash
composer lint       # vendor/bin/pint --test   (run `composer format` to fix)
composer analyse    # vendor/bin/phpstan analyse (level 8)
composer test       # vendor/bin/pest
composer ci         # all three
```

All three must pass. Add tests for every behaviour change and an entry under
`[Unreleased]` in `CHANGELOG.md`.

## Pull requests

- Keep pull requests focused on one change.
- Describe the problem, the change, and how it was tested.
- Link Apple's or Google's documentation when changing store-specific behaviour.
